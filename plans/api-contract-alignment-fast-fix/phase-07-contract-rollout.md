# Phase 7 — Contract test matrix, OpenAPI, and rollout evidence

## Objective

Prove the fast-fix contract end to end, publish an OpenAPI artifact for the separate frontend, and
retain a safe legacy fallback.

## Scope

- Build a matrix for every target operation in `app/api_contract.py` plus checklist routes: method,
  path params, query params, request schema, status, response schema, roles, and error codes.
- Add OpenAPI snapshot/assertion tests for camelCase names, prefixed IDs, envelopes, pagination, and
  no accidental legacy-only fields on target routes.
- Run clean migration/bootstrap, authorization, integration, scheduler benchmark, and legacy alias
  regression suites. Export versioned OpenAPI and a FE migration table.
- Add deprecation/successor headers and telemetry only where not already present; define a rollback
  switch and a follow-up issue for legacy removal after FE sign-off.

## Likely files and ownership

- `apps/api/app/api_contract.py`, `app/main.py`, `app/services/route_telemetry.py`.
- `apps/api/tests/test_openapi_contract.py`, `test_target_contract_matrix.py`, integration tests.
- `docs/api/` — generated OpenAPI/migration notes and known intentional deviations.
- `feature_list.json` only if the implementation workflow requires tracking phase evidence.

## Tests to write first

- Matrix test fails on a missing target operation or wrong path placeholder.
- OpenAPI schema test checks request aliases, response envelope, query params, and status codes.
- Role matrix covers ADMIN/MANAGER/LECTURER/STUDENT and archived-semester behavior.
- Clean database migration/seed, full integration, benchmark, and legacy alias smoke tests.

## Acceptance criteria

- All 53 spec operations plus explicitly approved checklist extensions are present in OpenAPI and
  have passing request/response/error evidence.
- Non-integration, integration, migration, benchmark, and legacy regression commands pass, or each
  failure is recorded with an owner and blocker status.
- A versioned OpenAPI export and endpoint migration matrix are handed to FE; target aliases have
  telemetry/deprecation metadata and a documented rollback switch.
- No unrelated root files or frontend changes are included in the release.

## Rollback

Keep legacy paths live and disable target aliases by config/route registry. Roll back the application
image only; retain additive migrations and data generated by valid scheduler/result workflows.
